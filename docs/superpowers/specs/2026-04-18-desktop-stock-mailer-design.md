# 本地桌面应用设计：股票列表管理、邮件发送与配置推送

## 背景

当前仓库已经具备以下能力：

- 通过 Yahoo 行情客户端拉取美股报价和历史数据。
- 基于 `daily-report` 流程生成每日美股收盘邮件。
- 使用环境变量读取 SMTP 发件配置并发送邮件。
- 已连接到 GitHub 远程仓库，可执行普通 `git push`。

用户希望在本地新增一个可双击打开的 Windows 桌面程序，用图形界面完成以下任务：

- 修改追踪的股票代码。
- 保存时自动校验代码是否有效，并把价格反馈给用户。
- 立即触发一次日报邮件发送。
- 一键提交并推送应用自己维护的配置文件到 Git 仓库。

## 目标

- 提供一个基于 Windows 的桌面窗口程序，后续可打包为单独的 `.exe`。
- 复用现有邮件与行情逻辑，避免复制 CLI 层代码。
- 将 GUI 管理范围限定为应用自有配置，避免误提交仓库中的其他改动。
- 在保存股票列表时给出明确校验反馈，阻止错误代码落盘。

## 非目标

- 不在 GUI 中保存 SMTP 账号、授权码或收件人地址。
- 不让 GUI 修改 `.env`、数据库、日志、构建产物或其他源码文件。
- 不实现复杂的多窗口流程、系统托盘、桌面通知或自动定时发送。
- 不在 v1 中开放邮件主题、时区、均线参数等高级配置编辑。

## 方案对比

### 方案 A：Tkinter + PyInstaller

- 优点：纯 Python，易于接入现有模块，依赖轻，打包成本低。
- 缺点：界面观感一般，但足够支撑工具型应用。

### 方案 B：PySide6/Qt + PyInstaller

- 优点：界面更现代，控件丰富。
- 缺点：依赖更重，打包更复杂，对当前需求过度设计。

### 方案 C：本地网页 + 桌面壳

- 优点：界面自由度高。
- 缺点：需要引入额外前端栈，与当前 Python 项目结构不匹配。

## 结论

采用方案 A：`Tkinter + PyInstaller`。

这是当前项目中风险最低、集成成本最低、最适合快速交付 Windows `.exe` 的实现路径。

## 总体架构

新增 GUI 层，但不直接复用 CLI 命令入口。GUI 将直接调用底层业务模块：

- 行情与日报构建：`polybot.reports.daily_stock`
- 邮件正文和图片渲染：`polybot.reports.email_renderer`
- 邮件发送：`polybot.notifications.emailer`
- 行情查询：`polybot.clients.yahoo_market_data`

新增模块建议放置在：

- `code/src/polybot/desktop/`

建议拆分为：

- `app.py`：Tkinter 应用入口与主窗口组装。
- `services.py`：保存、校验、邮件发送、Git 推送等用例服务。
- `config_store.py`：GUI 专属配置读写。
- `git_ops.py`：白名单 `git add/commit/push` 封装。
- `models.py`：GUI 用的数据结构与结果对象。

## 界面设计

单窗口布局，包含四个区域：

### 1. 股票列表编辑区

- 多行文本框，每行一个股票代码。
- 支持读取当前配置、编辑、恢复原值。
- 保存按钮只有一个，点击后自动执行清洗与校验。

### 2. 邮件发送区

- 一个“立即发送邮件”按钮。
- 使用 GUI 当前配置文件中的股票列表生成日报。
- 发件人、授权码、收件人全部继续从环境变量读取。

### 3. Git 推送区

- 一个提交说明输入框，默认值为 `Update tracked symbols`。
- 一个“预览变更”按钮。
- 一个“提交并推送”按钮。

### 4. 日志输出区

- 用于显示保存结果、报价反馈、发信结果、Git 输出和错误信息。
- 所有关键操作都要有可读的中文反馈。

## 配置文件策略

GUI 只维护一份正式配置文件：

- `code/config/gui/daily_report.yml`

初始化规则：

- 若文件不存在，则从 `code/config/daily_report.example.yml` 复制生成。

GUI 可修改字段：

- `symbols`

GUI 暂不修改字段：

- `timezone`
- `report_title`
- `mail.subject_prefix`
- `indicators`

上述字段保留在配置文件中原样存在，但 v1 不在界面里暴露编辑入口。

## 保存与校验流程

“保存股票列表”按钮行为如下：

1. 从文本框读取全部输入。
2. 去除空行、首尾空格，统一转为大写。
3. 按输入顺序去重。
4. 使用行情客户端批量查询每个代码的最新可用报价。
5. 若任一代码校验失败，则：
   - 阻止保存。
   - 弹出错误提示。
   - 在日志区列出失败代码及原因。
6. 若全部成功，则：
   - 将清洗后的 `symbols` 写入 `code/config/gui/daily_report.yml`。
   - 在日志区输出每个代码的最近价格或最近交易日数据，作为成功反馈。

用户体验约束：

- 保留一个保存按钮，不拆成“检查”和“确认保存”两步。
- 保存失败时不写盘，避免错误代码进入正式配置。

## 邮件发送流程

“立即发送邮件”按钮行为如下：

1. 读取 `code/config/gui/daily_report.yml`。
2. 通过 `build_daily_stock_report()` 构造报告数据。
3. 通过 `render_daily_stock_email()` 和 `render_daily_stock_table_png()` 生成正文与附件。
4. 从环境变量读取 SMTP 配置。
5. 通过 `send_email()` 发出邮件。
6. 将成功或失败结果写入日志区。

错误场景需要明确区分：

- 缺少环境变量。
- 行情数据拉取失败。
- 邮件渲染失败。
- SMTP 认证或发送失败。

## Git 推送流程

### 白名单原则

GUI 的 Git 操作只允许处理以下文件：

- `code/config/gui/daily_report.yml`

禁止行为：

- 不执行 `git add .`
- 不自动提交工作区中其他文件
- 不修改 `.env`
- 不写入 `.polybot/`、`build/`、`dist/`、数据库或缓存目录

### 预览变更

点击“预览变更”时：

- 显示白名单文件与 `HEAD` 的差异摘要。
- 若没有变更，明确提示“没有可推送的配置变更”。

### 提交并推送

点击“提交并推送”时：

1. 校验 Git 是否可用。
2. 校验当前目录是 Git 仓库且存在远程 `origin`。
3. 只暂存白名单文件。
4. 若白名单文件无变更，则终止并提示。
5. 以用户输入或默认提交信息执行提交。
6. 推送到当前分支对应的 `origin`。

失败反馈需要区分：

- Git 未安装。
- 当前目录不是仓库。
- 没有远程仓库。
- 认证失败。
- 网络错误。
- 当前分支无上游分支且无法推送。

## 数据流

### 保存股票列表

GUI 输入框 -> 清洗与去重 -> 行情校验 -> 成功则写入 GUI 配置文件 -> 日志反馈

### 发送日报邮件

GUI 配置文件 -> 报表构造 -> 邮件内容渲染 -> 环境变量读取 SMTP 配置 -> 发信 -> 日志反馈

### 提交并推送配置

GUI 配置文件 -> Git diff 预览 -> Git add 白名单文件 -> commit -> push -> 日志反馈

## 错误处理

错误处理遵循以下原则：

- 失败要阻断危险动作，例如错误代码不得保存。
- 所有异常都要转换成中文用户可读提示。
- 技术细节可以写入日志区，但弹窗文案要短。
- 网络类操作应在后台线程执行，避免阻塞主窗口。

建议引入后台执行策略：

- GUI 主线程只负责界面更新。
- 行情查询、邮件发送、Git 操作在后台线程运行。
- 线程完成后通过线程安全回调更新日志与按钮状态。

## 测试策略

优先测试非界面逻辑，避免把大量测试成本放在 Tkinter 控件本身。

需要覆盖：

- 股票代码清洗与去重。
- 保存前校验成功与失败路径。
- GUI 配置文件初始化与读写。
- Git 白名单暂存逻辑。
- 白名单无变更时的提示逻辑。
- 邮件发送服务在缺少环境变量时的失败路径。

测试目录建议新增：

- `code/tests/test_desktop_config_store.py`
- `code/tests/test_desktop_services.py`
- `code/tests/test_desktop_git_ops.py`

GUI 仅做轻量 smoke test，不在 v1 中引入复杂 UI 自动化。

## 打包与交付

目标交付物：

- Windows `.exe`

打包策略：

- 从 `code/` 目录执行 `PyInstaller`。
- 显式加入 `code/src` 作为导入路径。
- 补充隐藏依赖 `yfinance`。
- 为 `ZoneInfo("Asia/Shanghai")` 带上 `tzdata`。
- 将默认配置文件作为数据文件一并打包。

注意事项：

- 不直接 import `polybot.cli`，避免把 CLI 无关依赖一起拖入 GUI 包。
- 需要单独准备 GUI 启动入口，例如 `polybot.desktop.app:main`。
- 若选择单文件模式，首次启动可能较慢，可后续再评估 `--onefile` 和目录模式取舍。

## 风险与边界

- `yfinance` 结果存在外部数据源波动，校验结果应表述为“未查到有效行情”而非绝对断言代码无效。
- Windows 打包环境与开发环境不同，需在真实 Windows 上验证时区、SMTP、Git 与图像渲染。
- Git 提交依赖本机已有认证状态，GUI 不负责 GitHub 登录流程。

## 实施顺序

1. 新增 GUI 配置读写与初始化逻辑。
2. 新增股票列表清洗与行情校验服务。
3. 新增邮件发送服务封装。
4. 新增 Git 白名单预览、提交与推送逻辑。
5. 组装 Tkinter 主窗口与后台线程机制。
6. 补齐测试。
7. 增加打包脚本或文档，生成 `.exe`。
